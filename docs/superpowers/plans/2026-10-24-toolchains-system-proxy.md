# 工具链分发与系统代理实施计划

> **执行方式：** 本会话 inline 分阶段执行。每阶段结束运行对应测试并更新 `debug_state.md`。

**目标：** 让 Windows 安装版具备 ADB/fastboot、OpenSSH、Python 常用工具，并让 Qt 网络、MQTT 和按协议可支持的外部连接准确跟随 Windows 系统代理。

**架构：** 增加独立代理策略和工具链注册/解析服务，避免业务组件各自猜测代理或工具路径。安装包中的必备工具由锁定来源的构建脚本放入每用户工具目录；扩展工具仅在用户主动选择后下载、校验、解压并登记。设置页统一呈现来源、状态、路径和操作结果；卸载只处理受清单管理的文件。

**技术栈：** C++17、Qt 6.11.1（Network、Core、QML）、CMake/CTest、PowerShell、NSIS、Windows 系统代理发现。

## 执行状态（2026-10-24）

阶段 1–7 已完成，用户已验收并于 2026-10-24 授权正式发布 v1.2.0。此前完整 CTest 25/25 通过（105.41 秒），ZIP 测试 3 套通过；安装器隔离回归覆盖升级、两种卸载方式、同版本补齐工具及部署失败后仍可卸载。Android 下载修复也已实测并验收。发布阶段重新构建、完整测试和隔离验证后上传源码与正式包；隔离包不作为交付安装包。

实际实现将工具职责拆为 `ToolPaths` 和 `ToolManager`，使用各 `QNetworkAccessManager` 的独立代理工厂及 TCP/MQTT 目标代理，不设置影响 UDP/服务端的全局工厂。设置只显示固定“提供版本”和解析路径，不执行任意自选程序探测版本，也不保证能识别仅存在但不可启动的文件。完整 Windows PAC、SOCKS/TLS/认证代理和磁盘耗尽尚未实测；真实设备和用户实际代理环境仍待验收。系统代理检查入口为刷新只读快照，不主动探测互联网连通性。

## 全局约束

- 源码和文档使用 UTF-8；仅在 `C:\Test_Program\QT\SerialStudio` 工作区内读写。
- 工具查找顺序为高级设置指定路径 → SerialStudio 管理目录 → 系统 PATH；不得修改系统 PATH。
- 更新、扩展下载、HTTP、MQTT 使用系统代理或系统默认路由；SSH/ADB 仅在实现协议确实支持时接入代理，并显示真实状态。
- VPN/TUN 由操作系统路由处理，不把它描述为应用发现的代理。
- 下载先落临时文件，核对锁定的 SHA256 后再替换；失败不破坏已安装版本。
- 卸载保留或移除工具链由用户选择；移除范围只限清单记录且位于应用管理目录内的文件。
- 用户验收前不打正式安装包、不推送、不发布；不连接真实设备、不操作用户可见桌面。
- 每个阶段完成后更新 `debug_state.md`，报告构建新增警告和错误数。

## 文件与模块边界

- 新增 `src/systemproxy.{h,cpp}`：Windows 系统代理读取、代理变更监视、Qt 网络代理解析与连接状态文本。
- 新增 `src/toolpaths.{h,cpp}`、`src/toolmanager.{h,cpp}`：分别负责路径优先级/进程环境和受管清单/设置/安全下载部署。
- 修改 `src/main.cpp`、`CMakeLists.txt`：创建服务、注入 QML、链接测试目标。
- 修改 `src/updatecontroller.cpp`、`src/webdebugger.cpp`、`src/mqttclient.{h,cpp}`：统一系统代理策略并为 MQTT socket 设置经解析的代理。
- 修改 `src/terminalcontroller.cpp`、`src/adbdiscovery.cpp`、`src/filetransfer.cpp`：调用工具链解析器；仅对可验证支持的传输配置代理状态。
- 修改 `qml/pages/SettingsPage.qml`：展示系统代理状态、工具链状态、路径覆盖和扩展下载操作。
- 修改 `构建.ps1`、`制作安装包.ps1`、`installer/安装包.nsi`：校验并暂存必备工具、写工具清单、设置卸载保留/移除选择。
- 新增针对系统代理、工具路径/校验/清理边界的 C++ 测试；扩展现有设置页 QML 和安装器隔离测试。
- 新增 `tools/toolchains.json` 及对应来源/许可证说明：锁定平台、版本、下载地址、SHA256、许可、归档内路径及目标文件清单。

## 阶段 1：锁定依赖来源

1. 从官方发行源确定 Windows x64 ADB/fastboot、Python embeddable runtime 和可再分发 OpenSSH 的确切版本。
2. 对每个候选下载核对官方发布页、许可证、归档 SHA256、依赖 DLL 和运行入口；用隔离目录运行版本/帮助检查，禁止依赖当前 PATH。
3. 对不能确认来源、摘要、许可证或独立运行依赖的组件停止纳入安装包，并在设置中保留外部路径选择。
4. 写入 `tools/toolchains.json` 和 `第三方组件说明.md` 后执行清单格式测试及许可证/摘要核对。

**验收：** 每个随包组件都能追溯到固定版本、官方来源、摘要、许可证和架构；来源未锁定则不进入后续打包集成。

## 阶段 2：系统代理服务及测试

1. 新增 `SystemProxy`，解析 Windows 当前用户代理设置及系统代理列表，明确区分显式代理与系统默认路由。
2. 提供按 URL 解析代理的接口、只读状态和系统代理变更信号；未设置时不强行创建代理。
3. 在独立 `proxy_tests` 覆盖无代理、HTTP、HTTPS、SOCKS、排除列表、无效地址、变更刷新及回退默认连接。测试通过注入代理快照，不改真实 Windows 代理。
4. 为各 Qt HTTP 管理器安装独立代理工厂，TCP/MQTT 按目标设置 socket 代理，确保新请求查询最新策略，避免误影响 UDP 和 TCP 服务端。

**验收：** 单元测试逐项证明选择结果；未运行受控真实代理时不宣称代理连通性通过。

## 阶段 3：HTTP、更新与 MQTT 路由

1. 将更新检查、Release/工具下载和 HTTP 调试统一走系统代理解析；保留 TLS 校验、现有超时和摘要校验。
2. MQTT 的 `QTcpSocket`/`QSslSocket` 对目标地址解析代理；使用 Qt 支持的代理类型，遇到协议不匹配时给出“该连接使用系统默认路由/不支持当前代理类型”的准确状态。
3. 扩展 `mqtt_tests` 和 `web_tests`，用本地 HTTP CONNECT/SOCKS 受控代理验证 CONNECT、TLS 隧道、失败回退策略与直连无代理行为。

**验收：** 测试能证明代理请求确实到达代理端、目标服务未被绕过；证书和主机验证仍启用。

## 阶段 4：工具链查找与应用接入

1. 增加工具注册表和解析优先级：高级设置路径、应用管理目录、系统 PATH，并返回命中来源/版本/错误原因。
2. 将 ADB/fastboot、SSH/SFTP/SCP、Python 的启动点改为使用解析服务；用户显式路径失效时提示路径错误，不静默换用其他来源。
3. 添加测试覆盖路径优先级、缺少工具、不可执行文件、版本信息读取、路径含空格和设置持久化。
4. 对 SSH/ADB 代理分别实现能力核对和状态说明；USB ADB、串口、本机回环不经过互联网代理。

**验收：** 无工具时提供清晰修复入口；进程使用的绝对路径与 UI 显示一致；不修改全局 PATH。

## 阶段 5：扩展工具安全下载与设置页

1. 从锁定清单显示可选工具用途、来源、版本、许可、体积和已安装状态。
2. 仅由用户点击启动下载；下载用系统代理，支持取消，限制归档大小与展开路径，拒绝路径穿越、链接条目和摘要不符。
3. 在同一管理根目录 staging 解压并验证入口，再原子切换当前版本；失败清理 staging 并保留旧版。
4. 设置页提供只读代理来源/状态、检查按钮、工具路径选择/恢复自动、扩展安装和结果状态；高级设置仅展示维护选项。
5. 新增离线测试归档、错误 SHA256、取消下载、恶意路径条目、磁盘写入失败和已有版本保留用例。

**验收：** 下载不会裸连绕开系统代理；所有拒绝用例不改变既有安装目录。

## 阶段 6：安装、升级与卸载清单

1. 构建脚本下载固定官方归档到项目 `deps` 缓存，先验证 SHA256 再展开至每次独立的安装 payload；缓存错误摘要立即拒绝。
2. Python/ADB/OpenSSH 放在应用外的每用户数据工具目录；安装 payload 不包含用户配置，不把工具复制到 Windows/System32。
3. 安装器写入受管工具清单和版本元数据；升级完整替换应用文件，保留该目录并按清单迁移工具版本。
4. 卸载向导增加“保留工具链/移除受管工具链”选择；删除前 canonicalize 路径并逐项核对清单，仅删登记且位于受管根目录内的文件。
5. 扩展 `测试升级安装.ps1`、`验证安装包.ps1`：隔离安装/升级/两种卸载选项，检查配置、外部自选工具、未登记文件和 PATH 均保留。

**验收：** 安装和升级验证不触碰正式应用、真实用户配置或系统 PATH；NSIS 操作在独立测试根目录完成。

## 阶段 7：完整回归和验收状态

1. 在隔离 PATH 运行随包工具版本/帮助命令，确保不依赖当前机器预装工具。
2. 运行完整 CMake 构建与 CTest，运行 QML 检查和安装器隔离测试；记录警告、错误及环境限制。
3. 更新中文安装/工具/代理说明、版本变更说明和 `debug_state.md`，列明本机验证、未验证设备/外部代理情形。
4. 保留当前安装包与远程 Git 状态不变，提交用户验收的本地候选结果；正式打包、推送和发布由用户验收后另行授权。

**验收：** 所有自动化检查通过或将未通过项明确记录；真实代理和设备测试边界清楚。
