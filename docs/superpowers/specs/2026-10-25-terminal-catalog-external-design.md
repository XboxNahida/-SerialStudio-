# 外置指令库与独立同步设计

## 目标

将终端指令库从 Qt Resource System 中移出，使指令库可以独立更新而不重新发布 APP，同时保留离线初始库、版本校验、失败回滚和用户手动导入导出能力。

## 已确认范围

- APP 不再把 `data/terminal_commands.json` 编译进 `terminalcore`。
- 安装目录提供一份初始外置库：`catalog/terminal_commands.json`。
- 用户目录提供可写覆盖库，优先级高于安装目录。
- 指令库通过 GitHub Release 独立资源同步，不与 APP 安装包版本绑定。
- 下载结果必须经过 HTTPS、来源、大小、SHA-256、JSON 结构和版本兼容性校验。
- 更新采用临时文件和原子替换，保留上一份有效库以便回滚。
- APP 提供检查、下载并应用、导入、导出和恢复上一版本入口。
- 指令仍只用于候选、说明和填充，不自动执行命令。

## 文件与加载优先级

运行时按以下顺序选择有效指令库：

1. `%APPDATA%/SerialStudio/catalog/current.json`；
2. 安装目录 `catalog/terminal_commands.json`；
3. 若两者都不存在或校验失败，界面显示明确错误，不恢复 Qt 内嵌资源。

用户目录同时保存：

- `current.json`：当前生效库；
- `previous.json`：最近一次替换前的有效库；
- 当前库和上一版本均为单一版本封装 JSON，包含 `schemaVersion/catalogVersion/minAppVersion/commands`，保证版本与数据原子一致；维护源仍保留数组，构建时生成初始封装。

读取时必须验证 JSON 封装、版本、commands 数组、条目 `id/system/title/syntax/example` 字段、系统类型、重复 ID、文本安全限制和最大文件大小。手动导入兼容旧数组并标记版本 0.0.0。安装目录文件只读；用户目录更新必须使用 `QSaveFile` 或等价的临时文件提交。

## 同步协议

GitHub Release 为独立指令库的发布源，每个版本至少包含：

- `terminal-catalog-vX.Y.Z.json`；
- `terminal-catalog-vX.Y.Z.json.sha256`；
- `terminal-catalog-manifest.json`。

清单包含 `schemaVersion`、`catalogVersion`、`minAppVersion`、文件名、大小、SHA-256、发布日期和下载地址。APP 只接受 HTTPS 的 GitHub API/Release 资源域名，并沿用现有系统代理探测。检查阶段读取发布列表和清单；应用阶段下载 JSON，使用清单固定 SHA-256 验证后替换；单独摘要附件供人工和 CI 校验。

版本比较使用现有三段式版本规则，独立 Release 使用 `catalog-vX.Y.Z` 标签，APP 更新器不会将其当作 APP 版本。若 `minAppVersion` 高于当前 APP，保留当前库并提示需要升级 APP。网络失败、超时、摘要不符、结构不符或写入失败时，不改变当前库。

## 用户界面

设置页顶部固定显示“更新与指令库”区域，统一显示 APP 更新和指令库更新，但两者保持独立状态、独立下载、独立应用和独立忽略。该区域位于其他设置卡片之前，不随高级设置折叠隐藏。显示当前 APP 版本、指令库版本、来源、上次检查时间和状态，并提供：

- 检查 APP 更新；
- 下载并安装 APP 更新；
- 忽略当前 APP 版本；
- 检查指令库更新；
- 下载并应用指令库更新；
- 忽略当前指令库版本；
- 从 JSON 导入指令库；
- 导出当前指令库；
- 恢复上一版本指令库；
- 打开指令库目录。

导入前执行同样的结构校验；导出使用 UTF-8。更新完成后通知指令辅助窗口重新加载，已打开的编辑内容不被覆盖。

### 更新提醒

- APP 更新和指令库更新都在启动后的后台检查中参与检测；网络失败不阻塞主界面。
- 任一更新可用时，首次发现显示非模态弹窗提醒；用户可选择“立即处理”“稍后提醒”或“忽略此版本”。
- 主窗口设置入口显示小红点：APP 更新和指令库更新分别有独立标记，任一版本被忽略后不再显示对应标记，手动检查可重新显示。
- 弹窗不会自动安装 APP，也不会自动替换指令库；下载和应用仍由用户明确点击完成。
- APP 更新弹窗继续进入现有完整安装包流程；指令库更新弹窗进入独立 JSON 下载、校验和原子替换流程。

### 工具链缺失引导

- 终端、文件管理、ADB、SSH/SFTP、网络调试等功能在执行前检查所需工具链；缺失时在当前页面显示具体缺失组件、用途和“前往设置下载”按钮。
- “前往设置下载”按钮切换到设置页并定位到工具链卡片，保留当前设备和表单配置；用户完成下载后可返回原页面重试。
- 如果工具链卡片已经有该组件的下载任务，按钮显示任务状态并定位到对应进度，不重复创建下载。
- 工具链缺失提示不阻塞串口、本机 PowerShell/CMD 等不依赖该组件的功能。

## 错误处理与安全边界

- 不执行指令库中的任何字段，只把它们作为显示和填充文本。
- 下载响应限制大小，禁止符号链接或目录替换用户库目录。
- 写入前保留旧文件；提交失败时删除临时文件并保持旧库。
- 当前库损坏时优先尝试 `previous.json`，再尝试安装目录初始库，并报告实际采用的来源。
- 不修改系统 PATH、系统代理或用户现有设置。

## 验证范围

- 单元测试：路径优先级、结构校验、重复 ID、版本兼容、摘要验证、原子替换和回滚。
- 现有终端测试：四类系统的命令数量、搜索、候选和输入保护继续通过。
- 离屏 QML 测试：设置页按钮状态、状态文字、导入导出入口。
- 构建检查：无新增 C++ 警告或错误；安装目录包含 `catalog/terminal_commands.json`，Qt 资源中不再包含该文件。
